# 2026-07-27 Closet Index Development Log

## Work Summary

Notion에서 Supabase로 이미 이전된 구매일이 앱에서는 읽히거나 표시되지 않아, Closet과 추천 기능에서 활용할 수 있도록 프런트엔드 데이터 흐름을 연결했다. Closet은 구매일 최신순을 기본값으로 바꾸고, HOME에는 온도 안전성 추천과 구분되는 `최근 구매 착장` 영역을 추가했다.

## Work Completed

- 구매일이 없는 아이템은 구매일 정렬 방향과 관계없이 목록 마지막에 배치했다.
- Outfit 구성 아이템 중 가장 늦은 구매일과 해당 아이템 이름을 추천 결과에 포함했다.
- 구매일이 가장 최근인 최대 3개 Outfit을 `최근 구매 착장`으로 분리하고, 기존 기록 기반 추천 및 시험 착장과 중복 표시하지 않도록 했다.
- 최근 구매 착장 카드에 구매일, 최근 구매 아이템, 기존 온도 추천 단계를 함께 표시했다.
- 실제 Supabase 데이터에서 최신 구매일 값이 존재하는 것을 읽기 전용 쿼리로 확인했다.
- 구매일 정렬과 추천 분리를 포함해 단위 테스트 22개, 타입 검사, 프로덕션 빌드를 통과했다.
- 데모 데이터 기반 브라우저 검증에서 기본 최신순, 다른 정렬 선택, 상세 구매일, 최근 구매 착장 3개 영역과 콘솔 오류 없음까지 확인했다.

## Decisions

- Outfit의 대표 구매일은 구성 아이템 중 가장 최근의 `acquired_on`으로 정했다. 오래된 옷과 새 옷을 조합한 경우에도 새로 산 아이템을 입기 위한 착장으로 식별하기 위해서다.
- `최근`에 임의의 기간 기준을 두지 않고, 현재 추천 후보 중 구매일이 가장 최신인 최대 3개를 선택했다. 데이터 분포와 실제 사용 경험 없이 30일·90일 같은 기준을 고정하지 않기 위해서다.
- 최근 구매 착장은 온도 안전성을 의미하지 않으므로 기록 기반 추천과 별도 영역으로 분리했다. 카드에는 기존 `추천 높음`, `추천 가능`, `주의`, `시험 착장` 상태를 그대로 노출한다.
- 구매일 미입력 아이템은 최신순과 오래된순 모두 마지막에 둔다. 날짜가 없는 항목이 정상적인 시간 순서를 끊지 않도록 하기 위해서다.

## Decisions - Phase 1B 실제 회원 signed URL 검증

- `redirectTo` 계산은 현재 origin과 Vite base를 정확히 사용하고 있어 변경하지 않는다. 문제를 만든 임시 5178 포트를 원격 허용 목록에 넓히지 않고, 프로젝트가 이미 사용하는 5173 개발 주소를 고정한다.

- fresh OAuth를 위해 기존 회원 세션을 강제로 로그아웃하지 않는다. 이번 검증은 정상 복원된 실제 회원 세션으로 signed URL·RLS·화면 연결을 확인하는 범위다.
