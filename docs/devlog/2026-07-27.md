# 2026-07-27 Closet Index Development Log

## Work Summary

Notion에서 Supabase로 이미 이전된 구매일이 앱에서는 읽히거나 표시되지 않아, Closet과 추천 기능에서 활용할 수 있도록 프런트엔드 데이터 흐름을 연결했다. Closet은 구매일 최신순을 기본값으로 바꾸고, HOME에는 온도 안전성 추천과 구분되는 `최근 구매 착장` 영역을 추가했다.

## Work Completed

- `closet_items.acquired_on`을 Supabase 조회 결과와 앱의 `Item.acquiredOn` 필드에 연결했다.
- Closet 아이템 행과 아이템 상세 화면에 구매일을 표시했다.
- Closet 기본 정렬을 구매일 최신순으로 변경하고, 구매일 오래된순과 이름순 선택지를 추가했다.
- 구매일이 없는 아이템은 구매일 정렬 방향과 관계없이 목록 마지막에 배치했다.
- Outfit 구성 아이템 중 가장 늦은 구매일과 해당 아이템 이름을 추천 결과에 포함했다.
- 구매일이 가장 최근인 최대 3개 Outfit을 `최근 구매 착장`으로 분리하고, 기존 기록 기반 추천 및 시험 착장과 중복 표시하지 않도록 했다.
- 최근 구매 착장 카드에 구매일, 최근 구매 아이템, 기존 온도 추천 단계를 함께 표시했다.
- 실제 Supabase 데이터에서 최신 구매일 값이 존재하는 것을 읽기 전용 쿼리로 확인했다.
- 구매일 정렬과 추천 분리를 포함해 단위 테스트 22개, 타입 검사, 프로덕션 빌드를 통과했다.
- 데모 데이터 기반 브라우저 검증에서 기본 최신순, 다른 정렬 선택, 상세 구매일, 최근 구매 착장 3개 영역과 콘솔 오류 없음까지 확인했다.

## Decisions

- Outfit의 대표 구매일은 구성 아이템 중 가장 최근의 `acquired_on`으로 정했다. 오래된 옷과 새 옷을 조합한 경우에도 새로 산 아이템을 입기 위한 착장으로 식별하기 위해서다.
- `최근`에 임의의 기간 기준을 두지 않고, 현재 추천 후보 중 구매일이 가장 최신인 최대 3개를 선택했다. 데이터 분포와 실제 사용 경험 없이 30일·90일 같은 기준을 고정하지 않기 위해서다.
- 최근 구매 착장은 온도 안전성을 의미하지 않으므로 기록 기반 추천과 별도 영역으로 분리했다. 카드에는 기존 `추천 높음`, `추천 가능`, `주의`, `시험 착장` 상태를 그대로 노출한다.
- 구매일 미입력 아이템은 최신순과 오래된순 모두 마지막에 둔다. 날짜가 없는 항목이 정상적인 시간 순서를 끊지 않도록 하기 위해서다.

## Current Status

로컬 구현과 검증은 완료됐다. 기존 Supabase 스키마와 데이터만 사용하므로 새 마이그레이션이나 재이전은 필요하지 않다. 최근 구매 착장은 같은 최신 아이템이 여러 Outfit에 포함된 경우 여러 착장을 보여줄 수 있다. 변경 사항은 아직 커밋하거나 공개 사이트에 배포하지 않았다.

- 필요하면 `최근 구매` 기간 기준이나 같은 아이템이 포함된 착장 수 제한을 실제 사용 결과에 따라 조정한다.

## Work Summary - 비슷한 과거 착장

한 번도 입지 않은 계획 Outfit도 구성 아이템 대부분에는 과거 착용 근거가 있을 수 있다는 점을 추천 화면에 반영했다. 미착용 Outfit과 실제 착용 기록이 있는 저장된 Outfit을 비교해 가장 비슷한 과거 착장과 그 온도 기록을 `부분 근거`로 보여주되, 직접 착용한 기록으로 오해하지 않도록 기존 `시험 착장` 상태는 유지했다.

## Work Completed - 비슷한 과거 착장

- Outfit 구성 아이템 ID를 기준으로 가중 유사도를 계산하는 로직을 추가했다.
- 체감 온도에 영향이 큰 아우터·하의·원피스는 가장 큰 가중치, 상의·이너는 중간 가중치, 신발·양말은 작은 가중치, 가방·액세서리는 매우 작은 가중치로 처리했다.
- 가방·액세서리만 겹치거나 전체 유사도가 지나치게 낮은 Outfit은 온도 근거 후보에서 제외했다.
- 직접 착용 기록과 온도·체감 정보가 있는 Outfit만 과거 근거로 사용하고, 최대 3개의 유사 착장을 유사도·겹치는 아이템 수·착용 횟수·최근 착용일 순으로 계산했다.
- 시험 착장 카드에 `부분 근거 보통/낮음`, 최상위 유사 착장의 일치 아이템 수, 구성 아이템 중 과거 근거가 있는 수를 표시했다.
- Outfit 상세 화면에 비슷한 과거 착장 목록, 일치 비율, 착용 횟수, OK 온도 범위, 달라진 아이템을 표시했다.
- 직접 착용 기록이 생기면 부분 근거를 제거하고 기존 직접 근거 계산으로 자동 전환하도록 했다.
- 유사 착장 계산, 보조 아이템만 겹치는 예외, 직접 근거 전환을 포함한 회귀 테스트를 추가했다.

## Decisions - 비슷한 과거 착장

- 앱이 존재하지 않는 임의의 옷 조합을 만들거나 계절 조합의 가능성을 추측하지 않도록, J가 이미 저장한 Outfit끼리만 비교한다.
- 같은 하의의 체감 자체를 상의 조합에 따라 바꾸어 해석하지 않는다. 아우터·하의·원피스는 유사성을 판단하는 강한 기준점으로만 사용한다.
- 부분 근거는 미착용 Outfit의 안전성을 확정하지 않으므로 `추천 높음/가능`으로 승격하지 않고 계속 `시험 착장`으로 표시한다.
- 근거 신뢰도는 `높음`을 사용하지 않는다. 높은 구성 유사도와 비슷한 수준의 과거 착용 기록이 2회 이상일 때만 `보통`, 그 외에는 `낮음`으로 표시한다.
- 기존 Supabase 테이블 관계와 현재 내려받는 Item·Outfit·Wear Log 데이터만으로 계산할 수 있어 데이터베이스 마이그레이션은 추가하지 않았다.
