# 2026-08-01 Closet Index Development Log

## Work Summary

오늘 추천 근거가 전혀 없는 미착용 Outfit을 HOME에 계속 노출하는 대신, Closet과 Lookbook에서 필요할 때 찾아볼 수 있도록 짧은 `Unworn` 필터를 추가했다. HOME은 오늘 온도와 비교할 수 있는 직접 또는 부분 근거가 있는 착장만 보여주도록 역할을 좁혔다.

## Work Completed

- Closet 필터에 `Unworn` 체크박스를 추가하고, 해당 Item을 포함한 모든 Outfit의 Wear Log를 확인해 착용 기록이 0회인 Item만 표시하도록 했다.
- Closet의 `Unworn` 상태를 기존 카테고리·색상·Retired·정렬 필터와 함께 localStorage에 저장하고 필터 초기화에 포함했다.
- Lookbook 필터에 `Unworn` 체크박스를 추가하고, 해당 Outfit 자체의 Wear Log가 0회인 착장만 표시하도록 했다.
- 기존 `최근 90일 미착용`은 과거 착용 이력이 있는 Outfit도 포함하는 별도 필터로 유지했다.
- 추천 그룹에서 OK 온도 범위가 없는 미착용 Outfit 반환값을 제거하고 HOME의 `적정 온도 미확인 착장` 영역과 관련 더보기 상태를 삭제했다.
- Item·Outfit Unworn 판정, Closet 필터 상태 복원, 근거 없는 Outfit의 HOME 제외를 회귀 테스트로 고정했다.
- 데모 데이터의 활성 Item은 모두 착용 이력이 있어 Closet Unworn 결과가 빈 상태였으므로, 테스트에는 미착용 활성 Item fixture를 명시적으로 추가했다.

## Decisions

- 두 화면 모두 짧은 표기인 `Unworn`을 사용하되 판정 단위는 화면에 맞춘다. Closet은 Item 전체 이력, Lookbook은 정확한 Outfit 조합의 이력을 기준으로 한다.
- 보관·Error·Retired Outfit에 남아 있는 Wear Log도 실제 과거 착용 이력이므로 Item Unworn 판정에서 삭제하거나 무시하지 않는다.
- `Unworn`과 `최근 90일 미착용`은 의미가 다르다. 전자는 착용 0회이고 후자는 마지막 착용이 90일보다 오래됐거나 착용 기록이 없는 경우다.
- 온도 근거가 없는 Outfit은 추천 화면에서 추측 후보로 보여주지 않는다. 계절 범위와 Unworn 필터가 있는 Lookbook을 탐색 경로로 사용한다.

## Decisions - P3-6 Outfit Preview Cache

- Preview는 relation이 아니라 언제든 재생성 가능한 cache다. 따라서 생성 실패를 Outfit 저장 실패로 승격하지 않는다.
- 같은 Storage 경로를 upsert하지 않고 Outfit별 증가 version 경로를 사용한다. 새 object 검증과 ready 전환이 끝난 뒤에만 이전 ready를 비활성화한다.
- Database trigger와 browser fingerprint를 함께 사용한다. trigger는 저장된 relation·cutout 변경을 즉시 표시하고, fingerprint는 앱 composition 규칙 변경까지 포함해 stale cache 노출을 막는다.
- pending 또는 error가 최신 상태여도 마지막 정상 ready preview는 fallback으로 유지한다. 관리 상태와 실제 표시 가능한 cache를 별도로 판단한다.
- authenticated 사용자는 자기 workspace의 preview metadata 상태를 읽을 수 있지만 직접 insert·finalize하지 못한다. 쓰기는 인증 Edge Function과 service-role RPC 경계로 제한한다.
