## Decisions - 유지보수 리팩터링 client 릴리스 준비

- 누적 변경은 서로 의존하는 한 유지보수 릴리스로 함께 배포한다. 라우트 lazy loading과 vendor chunk, DataContext 분리, repository 계약 축소, clone client 제거를 일부만 선택하면 이미 검증한 타입·테스트·bundle 경계와 달라지기 때문이다.
- GitHub Pages workflow 자체에서 전체 테스트를 실행하도록 해 배포 build 전에 회귀를 차단한다.
- Outfit clone의 사용자 기능은 source-prefill 뒤 일반 create로 유지한다. 제거 대상은 별도 server clone client 계약뿐이다.
- `clone_closet_outfit` live RPC, grant, lifecycle COMMENT와 과거 migration은 이번 client 릴리스에서 변경하지 않는다.
- production DB cleanup은 compatible client 배포 성공, 공개 JavaScript 참조 0건, 실제 화면 확인 뒤 별도 migration으로 진행한다.
- CI 실패는 느린 native 이미지 통합 테스트의 제한만 조정한다. assertion과 900×900 입력, 500KB 목표, source local-only 검증을 그대로 유지해 테스트 강도를 낮추지 않는다.
