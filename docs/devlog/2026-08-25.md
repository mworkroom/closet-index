## Decisions - Import Runs cleanup migration 준비

- drift를 성공으로 오인하지 않도록 `IF EXISTS`를 사용하지 않고, 예상하지 못한 dependency를 함께 지우지 않도록 `CASCADE`를 사용하지 않는다.
- 긴 transaction이나 별도 policy DROP을 추가하지 않고 `DROP TABLE` 한 문장으로 lock 범위를 최소화한다. table 소유 object는 PostgreSQL이 함께 제거하되 외부 dependency가 생기면 migration이 실패한다.
- schema rollback과 data restore를 분리한다. 구조는 Git에서 검토 가능하게 유지하고, workspace UUID와 validation report가 포함된 2행은 ignored local file에서만 복구한다.
- 로컬 환경에는 Docker 명령이 없어 Supabase DB를 시작할 수 없다. production에서 test하지 않고 GitHub의 빈 PostgreSQL 17 환경을 격리 검증 기준으로 사용한다.
- multi-statement rollback은 한 prepared statement만 받는 `supabase db query`에 맞춰 동적 SQL로 변형하지 않는다. 원래 transaction과 사람이 검토하기 쉬운 DDL을 보존하고 격리 컨테이너의 표준 `psql`로 실행한다.
