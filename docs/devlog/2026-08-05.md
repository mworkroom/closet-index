## Decisions - Line 병합·보관·대표 Line

- 병합은 삭제가 아니라 source를 대표 Line에 연결된 archived 상태로 남긴다. 잘못 묶었던 기록을 다시 찾을 수 있고 대표 계보의 출처도 잃지 않기 위한 결정이다.
- 이미 다른 archived Line의 대표인 Line을 독립 보관하지 못하게 하고, 병합 시 기존 대표 참조를 새 target으로 한 단계에 다시 연결해 대표 chain이 길어지지 않게 했다.
- 독립 보관 Line만 직접 복원할 수 있고, 병합된 Line은 자동 분할 복원을 제공하지 않는다. membership·edge·start를 안전하게 역분배할 근거가 없기 때문이다.
- RPC는 `SECURITY DEFINER`의 빈 `search_path`, fully qualified relation, 함수 내부 workspace membership 검사와 `authenticated` 최소 실행 권한을 사용했다.
- production 변경은 별도 승인과 rollback 검증이 필요한 경계이므로 이번 작업에서는 read-only 데이터 감사와 migration·UI의 로컬 구현까지만 진행했다.

## Work Completed - Outfit 수정 화면 평가 표시 및 변경

- production DB에서 제보된 Outfit의 실제 rating이 `ok`임을 read-only로 확인했다.
- 수정 화면이 기존 Outfit rating을 초기값으로 불러오도록 변경했다.
- 검토 영역에 `Favorite`, `OK`, `Error` 평가 선택 컨트롤을 추가했다.
- 상단 상태 문구가 현재 선택된 평가를 즉시 표시하도록 변경했다.
- Outfit update input, Demo repository, Supabase repository에 rating을 포함했다.
- 기존 `closet_outfits.rating`을 이름·Item 구성과 같은 transaction에서 갱신하도록 `update_closet_outfit` RPC 확장 migration과 pgTAP 계약 테스트를 추가했다.
- 후속 의미 정리에서 `미입력`을 제거하고 평가 선택을 `Favorite`, `OK`, `Error` 세 가지로 축소했다.
- 새 Outfit과 복제 Outfit의 기본 평가를 `OK`로 변경했다.
- migration에 기존 NULL 6행의 `ok` 변환, column 기본값 `ok`, NOT NULL 제약과 legacy writer 정규화를 추가했다.

## Decisions - Outfit 수정 화면 평가 표시 및 변경

- 새 열을 추가하지 않고 기존 `closet_outfits.rating`을 사용한다.
- 수정은 원래 평가를 불러오지만 복제는 원본 평가를 복사하지 않는 기존 규칙을 유지한다.
- 평가와 Outfit 구성을 분리 저장하지 않고 기존 원자적 수정 RPC에 포함해 부분 저장을 방지한다.
- J의 평가 의미에서 미입력과 OK가 같으므로 별도 미입력 상태를 유지하지 않는다. 기존 NULL은 모두 OK로 흡수한다.
- DB를 먼저 적용해도 이전 공개 frontend가 깨지지 않도록 기존 `update_closet_outfit`을 과도기 호환 RPC로 유지하고, 새 frontend는 `update_closet_outfit_with_rating`을 사용한다.
