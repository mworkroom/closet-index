# 2026-08-06 Closet Index Development Log

## Work Summary

Phase 6의 첫 단계인 P6-1을 구현했다. 기존 Replacement Line의 확정 관계를 Item 상세에서 직접 부모, 현재 Item, 직접 자식 순서의 읽기 전용 계보로 확인할 수 있게 했다.

## Work Completed

- 기존 `loadEdges` 흐름을 재사용해 확정된 직접 관계만 계산하는 공통 selector를 추가했다.
- 월별 착용 분포와 포함된 Outfit 사이에 Replacement Line 영역을 배치했다.
- 다중 부모·자식, Retired 관계 Item, 부모별 선택 이유, 시작 Item 표시와 상세 페이지 이동을 구현했다.
- 관계가 없으면 영역을 숨기고, edge 조회만 실패하면 상세 페이지의 나머지는 유지한 채 영역 내부에서 다시 시도하도록 분리했다.
- 가로 스크롤과 현재 Item 강조, 키보드 focus를 포함한 모바일·접근성 스타일을 추가했다.
- selector 경계와 상세 화면의 표시·이동·오류 격리 테스트를 추가했다.

## Decisions

- 새 테이블이나 RPC를 추가하지 않고 기존 Replacement Line DB를 읽기 전용으로 사용했다. P6-1은 확정 관계 표시가 목적이며 기존 구조만으로 필요한 정보를 모두 얻을 수 있기 때문이다.
- 상세 기본 snapshot과 edge 조회를 결합하지 않았다. 계보 조회 실패가 Item의 기본 정보, 착용 통계, Outfit 표시까지 막지 않도록 오류 경계를 계보 영역에 한정했다.
- 자식으로 나가는 관계의 선택 이유는 현재 화면에서 숨기고, 부모에서 현재 Item으로 들어오는 이유만 부모별로 표시했다.

## Current Status

P6-1 집중 테스트 5개, 타입 검사, production build를 통과했다. 실제 연결 데이터가 있는 로컬 앱에서 데스크톱과 390×844 모바일 화면을 확인했고, Retired 현재 Item에서도 부모·현재·자식과 선택 이유가 보이며 자식 상세로 이동하는 것을 검증했다. 모바일 계보는 카드가 겹치지 않고 가로 스크롤로 끝까지 이동한다.

전체 회귀에서는 기존 `ReplacementLineagePage` 병합 테스트 1개가 단독으로도 실패했다. 병합 후 화면의 연결 전 Item 수는 `1 Item`인데 테스트는 `3 Item`을 기대하며, 이번 P6-1 변경 파일과 직접 관련되지 않아 임의 수정하지 않았다.
