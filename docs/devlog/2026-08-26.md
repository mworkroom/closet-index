## Decisions - Legacy Link Wave 3 재감사

- production DB와 업무 데이터는 이번 audit에서 변경하지 않는다. 18개 edge의 FK와 reverse·validation 분기가 남아 있으므로 table·RPC·column을 즉시 삭제하지 않는다.
- 초기 review/preview client workflow는 신규 pending 0개이고 현재 preview 저장도 구조적으로 잠겨 있어 제거 대상으로 확정한다. 다음 단계에서 importer, 숨은 route·page, review/confirm repository 계약과 source field client mapping을 먼저 제거·배포한다.
- 현재 계보의 source of truth는 119개 edge다. edge가 없는 directional Legacy Link 27개는 과거 판단 자료일 뿐 현재 graph에 자동 생성하지 않는다.
- client cleanup 배포 뒤 공개 JavaScript에 legacy route와 review/confirm RPC 문자열이 0개인지 확인한 다음에만 local-only export와 18개 edge 전환 migration을 준비한다.
- 전환 뒤 모든 edge가 manual이면 `source_kind`와 `source_legacy_link_id`를 역사 보존용 nullable field로 남기지 않고 FK·constraint·index와 함께 제거한다.
