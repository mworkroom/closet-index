# 2026-08-12 Closet Index Development Log

## Work Summary

아이폰에서 메인 화면과 Item 최초 등록 화면의 날짜 입력창이 카드 오른쪽 경계를 넘어가는 문제를 다시 점검했다. 기존의 폭 제한만으로는 Safari 네이티브 날짜 컨트롤의 내부 최소 폭과 외형을 충분히 제한하지 못할 수 있어 날짜 입력 전용 CSS를 보강했다.

## Work Completed

- `input[type="date"]`에 `width: 100%`, inline 축 기준의 최소·최대 폭, `box-sizing: border-box`, `overflow: hidden`, `appearance` 및 `-webkit-appearance`를 명시했다.
- `type="date"`와 날짜 선택 기능은 유지했다.
- Demo 모드 로컬 화면에서 Home과 `/closet/new`를 390px 및 340px 폭으로 확인했다.
- 두 화면 모두 날짜 입력창이 부모 패널 안에 들어오고 문서 가로 스크롤이 생기지 않는 것을 확인했다.
- 날짜 입력을 클릭했을 때도 입력 요소가 `type="date"`로 활성화되고 달력 아이콘이 유지되는 것을 확인했다.
- 집중 테스트 3개 파일 19개, 타입체크, 빌드를 통과했다.
- 전체 테스트와 `ItemDetailPage.test.tsx` 단독 실행에서는 관리 이력 영역을 찾지 못하는 3개 테스트가 실패했다. 날짜 입력 변경과 직접 관련 없는 별도 검증 이슈로 남겼다.

## Decisions

- 별도 JavaScript 날짜 선택기나 텍스트 입력으로 바꾸지 않고, iOS Safari의 네이티브 날짜 선택 경험을 보존하기 위해 `type="date"`를 유지했다.
- 실제 iPhone의 390px 화면을 Safari에서 약 115% 확대했을 때의 CSS 폭을 고려해 340px 조건도 함께 점검했다.
- 로컬 브라우저에서는 문제가 재현되지 않아 Safari 네이티브 컨트롤에서 발생할 수 있는 폭 재계산을 기준으로 CSS를 보강했다.

## Current Status

- 로컬 Demo 화면의 Home 및 Item 등록 날짜 입력창은 390px·340px 조건에서 패널 밖으로 튀어나오지 않는다.
- 로컬 브라우저 콘솔에는 오류와 경고가 없었다.
- GitHub Pages의 실제 화면은 인증 화면으로 전환되어 날짜 입력이 있는 배포 화면까지 확인하지 못했다. 배포 완료 상태로 간주하지 않는다.
- 실제 iPhone Safari에서 115% 확대 상태의 최종 확인은 아직 남아 있다.

## Next Steps

- 변경 사항을 배포한 뒤 실제 iPhone Safari에서 기본 390px 화면과 115% 확대 상태를 각각 확인한다.
- Item Detail 관리 이력 영역을 렌더링하지 못하는 3개 테스트는 별도 원인 분석이 필요하다.
