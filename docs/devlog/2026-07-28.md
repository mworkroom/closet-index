## Decisions

- 아이폰 캡처나 누끼 입력 파일이 100~1000KB로 다양해도 입력 단계에서는 허용한다. alpha trim·2.5% 안전 여백 뒤의 앱용 WebP 결과만 용량 기준으로 판정한다.
- 기존 결과와 재실행 호환성을 위해 첫 후보는 기존과 같은 1600px·quality 90·alpha quality 100을 유지한다. 목표를 넘는 파일에만 더 강한 압축을 적용한다.
- 500KB는 일반 목표이고 700KB는 안전 상한이다. 500~700KB 결과는 report 경고와 함께 허용하지만 700KB 초과 결과는 업로드하지 않는다.
- 누끼 생성 자체는 이번 작업 범위에 포함하지 않는다. 입력은 기존처럼 배경이 투명하고 Item 전체가 보이는 이미지여야 하며, 정사각형 프레임과 원본 해상도는 자동 trim 이후 배치 기준에 영향을 주지 않는다.
- 기존 원격 Batch 0 original 7개는 삭제하지 않는다. 새 도구로 cutout·preview만 사용하는 흐름을 먼저 검증한 뒤 별도 정리 단계에서 삭제 여부를 결정한다.

- HOME 카드에서 Outfit 제목, 아이템명 문장, 이동 화살표를 시각적으로 제거했다. 제목 데이터는 상세 이동 링크의 접근성 이름과 이미지가 없는 fallback 설명에 유지했다.
- 오른쪽 요약란에 선호도, 착용 횟수, `M/D/YY` 형식의 최근 착용일, 추천 수준, 적정 온도 범위, OK 횟수를 세로로 표시했다.
- 직접 착용 근거가 없는 Outfit은 `시험 착장`으로 구분하고, 유사 착장의 부분 근거 수준·온도 범위·OK 횟수를 표시하도록 했다.
- 추천 결과에 직접 착용한 OK 관측 횟수를 구조화된 `okObservationCount` 필드로 추가해 화면이 추천 문장 문자열을 해석하지 않도록 했다.
- HOME 카드 전용 렌더링 테스트와 추천 OK 횟수 테스트를 추가했다.
- 390×844 로컬 실제 데이터 화면에서 카드 폭 335px, 이미지 222px, 요약란 111px의 2:1 비율과 텍스트 잘림 여부를 확인했다.

## Decisions - HOME 착장 중심 카드

- 제목은 데이터에서 삭제하지 않고 HOME에서만 숨긴다. Lookbook과 상세 화면은 이번 변경 범위에서 유지하며, 이미지가 없는 소수의 착장도 기존 색상 fallback을 계속 사용한다.
- 직접 착용 근거와 유사 착장 근거를 같은 `추천 높음`으로 표시하지 않는다. 시험 착장은 직접 검증되지 않았다는 사실을 유지해 추천 신뢰도를 오해하지 않게 한다.
- 오른쪽 1/3의 좁은 폭에서도 판단 정보가 한눈에 들어오도록 문장형 선택 근거 대신 짧은 구조화된 항목을 사용한다.
