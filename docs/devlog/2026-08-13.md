# 2026-08-13 Closet Index Development Log

## Work Summary - Supabase 이미지 Egress 억제와 Statistics 목록 분할

Statistics 전체 Item 화면이 모든 결과를 한 번에 렌더링하고, Supabase 스냅샷 로딩 때 모든 이미지의 signed URL을 발급한 뒤 만료 시 전체 데이터를 다시 불러오던 구조를 정리했다. 화면에 가까운 이미지 파일만 내려받고 같은 파일은 세션 동안 공유하도록 바꿨으며, Statistics 목록은 24개 단위로 표시한다.

## Work Completed - Supabase 이미지 Egress 억제와 Statistics 목록 분할

- Supabase 스냅샷은 준비 완료된 이미지의 메타데이터와 Storage 경로만 읽고 signed URL을 일괄 생성하지 않도록 변경했다.
- signed URL 만료에 맞춘 전체 스냅샷 자동 새로고침을 제거했다.
- Item 이미지가 화면에서 600px 이내로 접근할 때 인증된 Storage 다운로드를 요청하는 지연 로딩 컨텍스트를 추가했다.
- 같은 Storage 경로의 동시 요청을 하나로 합치고, 생성한 Blob URL을 세션 캐시로 공유하도록 구현했다.
- Statistics 전체 Item 목록을 공통 배치 크기인 24개씩 표시하고 `더 보기`로 다음 24개를 노출하도록 변경했다.
- Statistics 상세 Item에서 뒤로 돌아오면 해당 필터 목록의 표시 개수를 복원하고, 새 필터로 이동하면 첫 렌더부터 24개로 제한하도록 처리했다.
- 이미지 메타데이터 로딩, 인증 다운로드의 경로 중복 제거와 부분 실패, UI 차원의 중복 이미지 요청 병합, Statistics 24개 분할을 테스트했다.

## Decisions - Supabase 이미지 Egress 억제와 Statistics 목록 분할

- private Storage의 signed URL을 모든 Item에 미리 발급하는 대신, 실제 표시가 가까운 이미지에만 인증 다운로드를 사용하기로 했다. 이 방식은 목록 데이터 조회와 이미지 바이너리 전송을 분리해 페이지 분할의 Egress 절감 효과가 실제 파일 요청에도 이어진다.
- Blob URL은 동일 Item 이미지가 여러 카드와 Outfit에 반복되어도 한 번만 생성해 공유한다. 컴포넌트별 캐시는 같은 파일을 중복 다운로드할 수 있어 앱 데이터 공급자 아래의 공용 컨텍스트에 캐시를 두었다.
- Statistics 배치 크기는 Closet에서 이미 사용하는 24개 상수를 재사용해 목록 경험과 정책을 일치시켰다.
- 새 필터에서 이전 목록의 큰 표시 개수가 한 프레임이라도 재사용되면 불필요한 이미지 다운로드가 시작될 수 있으므로, 필터 키가 달라진 렌더에서는 즉시 24개만 계산하도록 했다.
