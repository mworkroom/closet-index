## Decisions

- 날씨 조회와 추천 적용을 분리했다. API 응답 직후 결과가 조용히 바뀌지 않게 하여 J가 예보를 확인하고 선택할 수 있도록 했다.
- 출발·귀가 시각은 1시간 단위 선택으로 제한했다. 기상청이 실제로 반환하지 않은 시각을 자동 반올림하거나 보간하지 않기 위해서다.
- 별도 서버 캐시 테이블 없이 같은 탭의 session storage를 먼저 사용한다. 현재 호출량에서는 구조와 비용을 단순하게 유지하는 편이 안전하다.
- API 실패는 기존 추천 기능의 실패로 취급하지 않는다. HOME의 수동 입력은 항상 독립된 fallback으로 유지한다.
- 원격 DB·Edge Function 설정은 이번 작업에서 변경하지 않았다.

## Decisions - Phase 2 W6 Wear Log 출처 추적

## Work Completed - 상의 세로 위치와 신발 크기 재보정

- Supabase의 Outfit Item 위치값을 읽기 전용으로 집계해 Outer와 Top에 52px·56px 저장값, Shoes에 80% 저장값이 실제로 있는 것을 확인했다.

- 신발의 위 20px 위치, 하의와 신발의 독립적인 크기 계산, 가방 기본값은 유지했다.
- 합성 좌표·크기와 편집기 표시값 테스트를 새 기본값에 맞게 갱신했다.
- 첫 JSON 수정에서 동일한 `defaultScale` 필드 중 일반 상의 값이 잘못 80%로 바뀐 것을 집중 테스트가 발견했다. 일반 상의 90%를 즉시 복원하고 Shoes 규칙만 80%로 수정한 뒤 재검증했다.

## Decisions - 상의 세로 위치와 신발 크기 재보정

- 52px와 56px가 모두 반복됐으므로 기본값은 보수적으로 52px를 사용한다. 필요할 때 아래 화살표 한 번으로 56px에 도달할 수 있다.
- 기존에 숫자로 저장된 위치와 크기는 J의 명시적인 Outfit별 조정이므로 덮어쓰지 않는다. 새 기본값은 `NULL`인 미수정 Item과 원위치 버튼의 기준에 적용한다.
- 신발은 화면에 표시되는 placement 크기를 80%로 내려 J가 실제 편집기에서 선택한 값과 일치시킨다.
