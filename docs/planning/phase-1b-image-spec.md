# Closet Index Phase 1B Image Preparation & Normalization Spec

- 작성일: 2026-07-27
- 상태: 입력 규칙·Batch 0 슬롯·composition v1·인지 가능성 중심 품질 정책 확정, Item 14개와 Outfit preview 원격 업로드 완료
- 관련 문서: [Phase 1B Plan](./phase-1b-plan.md), [Pilot Outfits](./phase-1b-pilot-outfits.md)

## 1. 목표

J가 Item마다 직접 확대·축소·중앙 정렬하지 않아도 같은 누끼 하나를 여러 Outfit에서 일관되게 재사용할 수 있게 한다.

핵심 원칙:

- J는 배경이 투명하고 Item 전체가 보이는 누끼만 준비한다.
- 투명 여백 제거, 중심 계산, 카테고리별 크기 조정은 준비 도구가 자동으로 처리한다.
- 양말·신발·가방처럼 실제 크기와 카드에서 보여줄 크기가 다른 항목은 카테고리 기본 배율로 처리한다.
- 자동 배치로 해결되지 않는 소수 Item만 개별 `scale`, `position_x`, `position_y` override를 사용한다.
- 원본 누끼는 수정하지 않고, 정규화와 합성 결과를 언제든 다시 만들 수 있게 한다.

## 2. J가 준비할 이미지

권장 입력:

- 투명 배경 PNG 또는 WebP
- Item 하나가 완전히 보이는 이미지
- 세로·가로 방향은 실제로 앱에서 보이길 원하는 방향
- 가능하면 긴 변 1200px 이상
- 가능하면 sRGB 색상

입력 출처는 하나로 통일하지 않는다.

- iPhone으로 직접 촬영한 원본에서 만든 누끼
- 과거 옷장 앱의 Item 상세 화면을 캡처해 만든 누끼
- 쇼핑몰 상품 사진에서 만든 누끼
- 이미 별도로 보관 중인 이미지에서 만든 누끼

출처나 원본 해상도보다 최종 화면에서 Item을 알아볼 수 있는지가 우선이다. 긴 변 1200px 이상은 재가공 여유를 위한 권장값이지 업로드 필수 조건이 아니다. 긴 변이 500~1200px인 캡처 기반 이미지도 Item 전체와 주요 색·형태를 알아볼 수 있으면 허용하며, 작은 입력을 억지로 확대하지 않는다.

J가 하지 않아도 되는 작업:

- 정사각형 또는 특정 캔버스 크기에 맞추기
- 투명 여백을 정밀하게 자르기
- Item을 캔버스 중앙에 놓기
- 카테고리에 따라 직접 축소하기
- iPhone 앱에서 보던 크기에 맞추기
- WebP로 최적화하기

피해야 할 입력:

- Item 일부가 잘린 이미지
- 불투명한 흰색 배경
- 여러 색상의 다른 Item이 한 파일에 섞인 이미지
- 아주 작은 이미지를 억지로 확대해 흐려진 파일
- 누끼 주변에 큰 그림자나 장식이 포함된 이미지

신발·양말처럼 한 쌍인 물건은 J가 최종 카드에서 보고 싶은 모습 그대로 한 파일에 넣는다. 한 짝만 보이길 원하면 한 짝, 한 쌍이 보이길 원하면 한 쌍을 하나의 Item 이미지로 준비한다.

### 2.1 충분한 화질의 판정 기준

Phase 1B 이미지의 목적은 원본 사진을 감상하거나 확대 보존하는 것이 아니라 Closet과 Outfit에서 어떤 Item인지 빠르게 알아보는 것이다.

다음 조건을 만족하면 충분한 화질로 본다.

- iPhone의 Closet 목록과 Item 상세에서 Item 종류·색·대략적인 형태를 구분할 수 있다.
- Outfit preview에서 다른 Item과 혼동하지 않는다.
- 압축 흔적이 조금 보여도 선택과 착용 기록에 방해가 되지 않는다.
- Retired Item은 이미지가 없어도 되며, 필요할 때만 과거 앱 캡처를 사용한다.

고해상도 자체는 합격 기준이 아니다. 같은 Item을 알아보는 데 차이가 없다면 더 작은 파일을 선택한다.

## 3. 자동 정규화 과정

```text
J의 투명 누끼
→ alpha 영역으로 실제 Item 경계 계산
→ 불필요한 투명 여백 제거
→ 2~3% 안전 여백 추가
→ 카테고리별 slot 크기에 비율 유지 fit
→ 카테고리별 anchor에 정렬
→ 필요한 경우 Item별 override 적용
→ Outfit preview 합성
```

### 3.1 투명 여백 제거

- 이미지 전체 크기가 아니라 불투명·반투명 픽셀이 존재하는 실제 경계 상자를 사용한다.
- 누끼 앱이 만든 캔버스 크기나 중심 위치가 파일마다 달라도 결과에 영향을 주지 않는다.
- 가장자리 털, 니트 보풀, 반투명 그림자가 잘리지 않도록 낮은 alpha threshold와 작은 안전 여백을 둔다.

### 3.2 비율 유지

각 Item은 다음 계산으로 slot 안에 맞춘다.

```text
scale = min(slot 최대 너비 / Item 실제 너비,
            slot 최대 높이 / Item 실제 높이)
```

- 가로세로 비율을 바꾸지 않는다.
- slot을 채우기 위해 늘여 찌그러뜨리지 않는다.
- 작은 원본을 화질이 깨질 정도로 확대하지 않는다.

### 3.3 카테고리별 anchor

단순한 이미지 중앙점 하나만 사용하지 않는다.

| 카테고리 | 정렬 기준 |
|---|---|
| 목 액세서리 | 실제 경계의 가로 중앙과 위쪽 기준 |
| 아우터 | 가로 중앙과 위쪽 기준 |
| 상의 | 가로 중앙과 위쪽 기준 |
| 하의·원피스 | 가로 중앙과 위쪽 기준 |
| 양말 | 가로 중앙과 아래 기준, 가장 낮은 z-index |
| 신발 | 가로 중앙과 바닥선 기준 |
| 가방 | 실제 경계의 중앙 |

신발과 양말은 중심점보다 바닥선을 맞추는 편이 서로 다른 높이의 이미지에서도 안정적이다.

## 4. 카테고리 기본 크기

정확한 좌표는 Batch 0 누끼 7개로 확정하지만 크기 관계는 다음과 같이 고정한다.

| 종류 | 상대 크기 |
|---|---|
| 아우터 | 가장 큼 |
| 하의·원피스 | 큼 |
| 오른쪽 상의 | 중간 |
| 가방 | 중간 |
| 신발 | 작음 |
| 목 액세서리 | 작음 |
| 양말 | 가장 작음 |

900 × 1200 preview 기준 초기 최대 영역:

| Slot | 최대 너비 | 최대 높이 |
|---|---:|---:|
| main-neck | 38% | 16% |
| main-outer | 48% | 38% |
| main-bottom | 42% | 38% |
| main-socks | 18% | 13% |
| main-shoes | 30% | 16% |
| side-top | 30% | 28% |
| side-bag | 30% | 28% |

이 값은 J가 누끼를 만들 때 맞출 규격이 아니다. 합성 도구의 자동 배율 초기값이며 첫 시안에서만 조정한다.

## 5. 예외 처리

자동 규칙으로 대부분을 처리하고 다음 경우에만 Item별 override를 둔다.

- 롱코트처럼 같은 Outer에서도 유난히 긴 Item
- 작은 숄과 큰 머플러처럼 크기 차이가 큰 목 액세서리
- 니삭스와 짧은 양말처럼 형태가 크게 다른 Socks
- 토트백과 작은 크로스백의 시각적 크기 차이
- 한 파일 안의 신발 두 짝 간격이 지나치게 넓은 경우
- 누끼 자체의 비대칭 때문에 기하학적 중앙이 어색한 경우

override:

```text
scale       기본 크기에 곱할 보정값
position_x  좌우 이동
position_y  상하 이동
z_index     레이어 순서
```

보정값은 원본 이미지에 적용하지 않고 `closet_outfit_items` 또는 별도 manifest에 기록한다. 같은 Item을 여러 Outfit에서 항상 같은 방식으로 보정할지, 특정 Outfit에서만 보정할지는 Batch 0 결과로 결정한다.

## 6. Batch 0 검증

첫 Favorite Outfit의 7개 Item으로 다음을 확인한다.

- 목 액세서리와 아우터의 간격
- 아우터와 하의의 상대 크기
- 일반 상의는 오른쪽 보조열에, 이너웨어는 아우터 아래 레이어에 배치되는지
- 이너웨어가 아우터와 하의 사이에서 필요한 만큼만 보이는지
- 양말이 자동으로 충분히 작아지는지
- 양말이 최하단 레이어, 신발이 그 앞에 보이는지
- 오른쪽 가방과 왼쪽 주열의 간격이 지나치게 넓지 않은지
- 전체 Outfit이 3열 Lookbook thumbnail에서도 식별되는지

Batch 0에서 slot 기본값을 한 번 확정한 뒤 Batch 1 누끼 12개를 합성한다. Batch 1에서 반복적으로 같은 보정이 필요하면 개별 Item 문제가 아니라 카테고리 기본값 문제로 보고 slot 설정을 수정한다.

## 7. Batch 0 레이어와 미세 위치 조정

Batch 0 2차 시안에서 가장 위에 보이는 레이어부터 다음 순서로 고정했다.

```text
목 액세서리
아우터
이너웨어
하의
신발
양말
```

- `Top-T-shirts-innerwear`처럼 이너웨어 역할인 Item은 오른쪽 `side-top`이 아니라 왼쪽 `main-innerwear`에 배치한다.
- 이너웨어는 아우터 뒤에 깔고, 하의가 시작되기 전 좁은 구간에서만 하단이 보이게 한다.
- 일반 상의는 기존처럼 오른쪽 `side-top`을 사용한다.
- 가방은 오른쪽 보조열을 유지하되 왼쪽 주열과 가까운 기본 위치를 사용한다.

자동 배치 뒤 예외적인 위치 보정이 필요하면 자유 드래그보다 네 방향 화살표를 사용한다.

- 한 번 누를 때 4px 이동
- 길게 누르면 같은 방향으로 연속 이동
- 이동값은 `position_x`, `position_y`로 저장
- `원위치`로 해당 Item의 이동값만 0으로 복원
- 크기 조정은 기본 화면에 두지 않고 실제 예외가 확인될 때만 별도 override로 제공

## 8. 파일 용량과 원격 저장 정책

Supabase에는 앱 운영에 필요한 최적화 결과만 기본 저장한다.

| 종류 | 원격 저장 | 기준 |
|---|---|---|
| 입력 원본·고해상도 PNG | 기본 저장 안 함 | 누끼 검증과 재처리 동안 로컬에만 임시 보관 |
| Item 누끼 | 저장 | 투명 WebP, 긴 변 최대 약 1600px, quality 90 |
| Outfit preview | 저장 | 투명 WebP, 900 × 1200px, quality 90 |

용량 목표:

- Item 누끼는 보통 50~500KB 범위를 기대하고 700KB 초과 시 경고한다.
- Outfit preview는 350KB 이하를 목표로 한다.
- 입력 파일 용량은 합격 기준으로 사용하지 않고 준비 도구가 정규화한 결과를 검사한다.

Batch 0 실측에서 Item 누끼 7개는 총 약 1.15MB, 평균 약 164KB였고 Outfit preview 1개는 약 132KB였다. 이 평균을 현재 Item 451개와 Outfit 507개 전체에 단순 적용하면 앱 표시용 이미지 예상치는 약 141MB다. 고해상도 원본을 제외하면 Supabase Free Plan의 1GB Storage 안에서 충분한 여유가 있다.

정책 변경 전에 업로드된 Batch 0 original PNG 7개 약 12.78MB는 즉시 삭제하지 않는다. 준비·업로드 도구와 metadata 계약을 새 정책에 맞춘 뒤, cutout과 preview의 원격 읽기 및 재생성이 확인된 별도 정리 단계에서만 삭제 여부를 결정한다.

## 9. 결론

J는 Item의 실제 크기, 이미지 캔버스 중심, 양말 축소 비율을 맞출 필요가 없다. 배경이 투명하고 Item 전체가 보이는 누끼를 준비하면 나머지는 자동 정규화한다.

예외 보정은 가능하지만, 모든 이미지를 사람이 드래그해 맞추는 흐름을 다시 만들지는 않는다.

이미지 품질은 고해상도 보존이 아니라 Item 인지 가능성으로 판단한다. iPhone 촬영본, 과거 앱 캡처, 쇼핑몰 이미지가 섞여도 최종 Item을 알아볼 수 있으면 같은 준비 과정으로 사용하며, Supabase에는 최적화된 누끼와 Outfit preview만 기본 보관한다.
